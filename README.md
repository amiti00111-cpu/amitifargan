# דף נחיתה — ליווי אונליין בכושר ותזונה

פרויקט Vite קל עם JavaScript מודולרי, CSS ו־RTL. אין שרת לשליחת לידים בפרויקט.

העיצוב משתמש בשחור ולבן, עם כחול כהה להדגשות. תמונת הפתיחה היא קובץ `IMG_4878.heic` שסופק: המאמן עומד בחדר הכושר בגופייה שחורה. היא הומרה לגרסאות WebP רספונסיביות ללא שינוי בתוכן התמונה, ומעליה שכבת שחור של 40%. בדסקטופ הטקסט והתמונה יוצרים אזור אחד בפריסה של כ־58/42; במובייל הכותרת, התיאור והכפתור קודמים לתמונה בעלת גובה מבוקר. קובצי תוצאות ה־JPG עדיין לא זמינים במרחב העבודה. ארבעת הזוגות והסדר שסופקו שמורים בנתונים; יש להזין את התמונות עצמן ל־`public/images/` כדי לחבר אותן לקרוסלה.

## הפעלה

נדרש Node.js 20.19+ או 22.12+ (בסביבה נבדק Node.js 24).

```sh
cd /workspace/amitifargan
npm ci
npm run dev
```

`npm run build` יוצר את `dist/`. `npm run preview` מציג את הבנייה. בפריסה, יש להגיש את `dist/` דרך אחסון סטטי או שרת HTTP.

## Vercel

`vercel.json` מגדיר Framework של Vite, פקודת בנייה `npm run build` ותיקיית פלט `dist`. אפשר לייבא את הריפו ב־Vercel מתוך GitHub. האתר הסטטי אינו דורש משתני סביבה כדי להיבנות. אימות חשבון Vercel לצורך פריסה צריך להתבצע דרך החיבור המאובטח או דרך חשבון Vercel של בעל האתר; אין להכניס טוקנים לקוד או לריפו.

## תוכן

הקופי והנתונים נמצאים ב־`src/data/content.js`. הקופי השיווקי מקורו בטקסט ובבריף שסופקו בשיחה; סוגריים מרובעים מציינים תוכן חסר. לא נוספו שמות, תוצאות, הבטחות או המלצות. מקטעי המלצות ושאלות נפוצות מוכנים בקוד ומופיעים רק כשמוסיפים להם נתונים אמיתיים. הודעות תפעוליות לטופס מסומנות כ־placeholders וניתנות להחלפה באותו קובץ.

## תמונות

שמרו תמונות ב־`public/images/`, והגדירו אותן ב־`content.js`. למשל, בתוך `hero.image`:

```js
{ src: '/images/hero.webp', alt: '[תיאור התמונה שסופק]', width: 900, height: 1100 }
```

אפשר להוסיף `srcSet` ו־`sizes` לכל תמונה. הערכים ב־width/height צריכים לתאר את הקובץ האמיתי. מומלץ לספק WebP/AVIF בגדלים מתאימים. לתמונות תוצאות יש `object-fit: contain` כדי לשמור על הגוף בשלמותו; תמונות מתחת לאזור הפתיחה נטענות עצלנית.

תמונת הפתיחה מחוברת כעת ל־`coach-480.webp`, `coach-960.webp` ו־`coach-1440.webp`. הגודל נבחר אוטומטית באמצעות `srcSet`. חיתוך תמונת הפתיחה בלבד מותאם למובייל ולמחשב דרך `.hero-photo .hero-media img` ב־`styles.css`. עוצמת ההכהיה מוגדרת ב־`.hero-overlay`; היא אינה משנה את קובץ התמונה המקורי.

בתוך `results.items`, כל פריט מייצג זוג אחד ודאי. `sourceFile` בכל תמונה שומר את שם הקובץ שהמשתמש הגדיר; הוסיפו `src`, `width` ו־`height` אחרי שקובץ התמונה נגיש. השתמשו ב־`image` לתמונת לפני/אחרי משולבת, או ב־`before` ו־`after` לשתי תמונות נפרדות. לכל אחת מבנה זהה לתמונת ה־Hero. אפשר להוסיף `name`, `duration` ו־`detail` רק כאשר המידע סופק. ״לפני״ נמצא מימין ו״אחרי״ משמאל, עם כיתובים מחוץ לתמונה. הקרוסלה עוברת בין זוגות באמצעות חצים, מקלדת ו־Swipe; ב־RTL החלקה ימינה חושפת את הזוג הבא שנמצא משמאל. בקצוות הניווט נעצר. בפריט יחיד החצים מושבתים; אין מקטע כשאין פריטים. ברשימות ארוכות המונה מחליף את הנקודות. פריטים ללא תמונות נשארים placeholders נפרדים ומסומנים.

## טופס, CRM ו־WhatsApp

החיבורים נמצאים ב־`src/config/site.js`. הגדירו `form.endpoint` ל־HTTPS endpoint אמיתי. הטופס שולח `POST` עם JSON `{ name, phone, goal }`; הצלחה מוצגת רק אחרי תגובת HTTP מוצלחת. ה־endpoint חייב לבצע validation בצד השרת, לטפל במידע ולהחזיר סטטוס הצלחה מתאים. חיבור ל־CRM ול־webhook עם סודות צריך להתבצע בצד השרת; אין לשים API keys בקוד דפדפן. בלי endpoint לא נשלח מידע ולא מוצגת הצלחה מדומה. הטופס לא שומר פרטים ב־localStorage.

ל־WhatsApp הגדירו `contactMode: 'whatsapp'` ו־`whatsappNumber` עם קידומת מדינה וספרות בלבד. `whatsappMessage` אופציונלי; הכניסו אליו רק טקסט מאושר. עד להגדרה, כל ה־CTA מובילים לטופס. הטופס עצמו עדיין צריך endpoint אם רוצים לשלוח ממנו לידים.

## SEO ופרטי קשר

ה־title וה־description ב־`index.html` משתמשים בקופי שסופק. כתובת canonical ותמונת Open Graph מוגדרות ב־`site.seo`. הוסיפו רק כתובת ותמונה סופיות. פרטי Footer וקישורים נמצאים ב־`content.footer`; אין קישורי קשר או פרטי עסק מומצאים.

## מבנה

- `src/components/` — מקטעי הדף וההתנהגות שלהם.
- `src/data/content.js` — הקופי וכל הרשימות.
- `src/config/site.js` — יעד שליחה, WhatsApp ו־SEO.
- `src/styles.css` — משתני עיצוב, רכיבים ו־breakpoints.
- `src/lib/` — helpers קטנים ל־HTML ולמדיה.
- `public/images/` — התמונות שמספקים.

לבדיקת אינטגרציה אמיתית נדרש endpoint אמיתי ותמונות אמיתיות. ה־placeholders אינם מציגים תוצאות לקוחות.
